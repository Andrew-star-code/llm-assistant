# eval

Оценка качества (§10.6, §18). Прогоняется при смене моделей, чанкинга и параметров поиска.

| Набор | Что считает | Запуск |
| --- | --- | --- |
| `rag/` | hit@5 и MRR поиска по базам знаний для четырёх конфигураций: только dense, только BM25, гибрид без реранкера, гибрид с реранкером; разбивка по типам вопросов (точные коды, словоформы, перефразы, английские термины) | `make eval-rag` (на моделях стенда) или `uv run python eval/rag/run.py [--check] [--json report.json]` с `APP_*` |

`rag/corpus/` — небольшой корпус документов, `rag/questions.yaml` — вопросы с ожидаемыми документами.
Корпус индексируется тем же кодом, что и базы знаний, в отдельную коллекцию `eval_rag_chunks`
(удаляется после прогона). `--check` завершается с ошибкой, если рабочая конфигурация (гибрид с
реранкером) хуже любой другой по hit@5 или MRR.

Цифры имеют смысл только на настоящих моделях (bge-m3 и bge-reranker-v2-m3 на сервере): на дев-стенде
эмбеддинги и реранкер — заглушки fake-llm. По eval подбираются порог реранкера, глубина prefetch и
`rag.search.bm25.avg_len`. Дальше здесь появится `scenarios/` (промпты, этап 5).
