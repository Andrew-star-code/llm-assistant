# services/fake-llm

Назначение: OpenAI-совместимый mock LLM для разработки без GPU и для детерминированных тестов (§16.1).
Повторяет формат vLLM: размышления отдельным полем дельты, `tool_calls` по кускам, usage последним чанком.

Публичный интерфейс:

| Эндпоинт | Что делает |
| --- | --- |
| `POST /v1/chat/completions` | Ответ по сценарию; `stream: true` — SSE-чанки как у vLLM |
| `POST /v1/embeddings` | Детерминированные нормированные векторы («мешок слов»: общие слова → близкие векторы) |
| `POST /v1/rerank`, `POST /rerank` | Реранк в формате vLLM/Jina (`documents` → `results`) или TEI (`texts` → список `{index, score}`): балл — доля основ слов запроса (первые 5 букв) в документе |
| `GET /v1/models`, `GET /health` | Список моделей, проверка живости |

Сценарий выбирается маркером в последнем сообщении пользователя, например
`[[scenario:tool_call_search]] найди регламент отпуска`. Без маркера — `default`,
а при `chat_template_kwargs.enable_thinking: true` — `thinking`.

| Сценарий | Поведение |
| --- | --- |
| `default` | Обычный стрим: «Это ответ fake-llm на запрос: «…»» |
| `thinking` | Сначала размышления (`reasoning`), затем ответ |
| `markdown` | Формулы во всех делимитерах, таблица, блок кода — для тестов рендера |
| `markdown_slow` | То же медленно — рендер незакрытых блоков во время стрима |
| `tool_call_search` | Вызов `search_knowledge_base(query)`; после сообщения `tool` — финальный ответ со ссылкой `[1]` |
| `moderation` | Явное нарушение: вызов скрытого `report_incident` (категория `illegal`, цитата — текст запроса), после ответа инструмента — нейтральный отказ «Извините, с этим запросом я помочь не могу.» |
| `find` | Ищет в системном промпте и результатах инструментов строку с текстом в «кавычках» (или со всем запросом): «Нашёл в документе: …»; если строка из пронумерованного фрагмента RAG — добавляет цитату `[n]` |
| `tool:<имя>[+<имя>…]` | Вызов инструментов этапа 3 с типовыми аргументами (несколько — параллельно): `create_spreadsheet`, `create_csv`, `create_document` (DOCX с формулами), `create_pdf`, `create_presentation`, `read_document` (файл — первый из промпта, страница — «стр. N» из запроса), `get_document_outline`, `read_spreadsheet`, `search_in_documents`, `list_attachments`; после сообщений `tool` — «Готово. Результат инструмента: …» (строка с текстом в «кавычках» или начало результата) |
| `tool_loop` | Бесконечно вызывает `list_attachments` — проверка лимита итераций |
| `error_500` | HTTP 500 |
| `disconnect` | Часть ответа, затем обрыв соединения без `[DONE]` |
| `slow` | 40 слов с паузой `FAKE_LLM_SLOW_DELAY_S` перед каждым — для «Стоп» и перезагрузки посреди стрима |
| `title` | Короткий ответ — для автозаголовков |

Кроме маркеров fake-llm следует трём строкам из `config/prompts`: в первом ответе диалога обращается к
пользователю из строки `Обращение к пользователю: …` системного промпта, а на запрос заголовка
(`Придумай короткий заголовок`) возвращает первые слова сообщения, на переформулировку для поиска
(`Переформулируй запрос`) — само сообщение без маркера сценария; имя файла для `read_document` берёт
из заголовка вложения `=== Файл «…»` (`system/attachments.md.j2`).

Настройки (переменные окружения): `FAKE_LLM_PORT` (8080), `FAKE_LLM_SLOW_DELAY_S` (0.3),
`FAKE_LLM_REASONING_FIELD` (`reasoning` | `reasoning_content` | `both` — имя поля в разных версиях vLLM),
`FAKE_LLM_EMBED_DIM` (1024), `FAKE_LLM_MODELS` (список через запятую).

Зависит от: ничего.

Точки расширения: новый сценарий — ветка в `src/fake_llm/scenarios.py::resolve` + имя в `SCENARIO_NAMES` + тест.

Данные: нет.

Тесты: `services/fake-llm/tests/` — через официальный SDK `openai` против настоящего uvicorn;
запуск — `make test` или `uv run pytest services/fake-llm/tests`.

**Guard-модель.** Запрос к модели `fake-guard*` отвечает как Qwen3Guard: `Safety: Unsafe` и
`Categories: Violent`, если в сообщении есть `[[guard:unsafe]]`, «взорвать» или «отравить»; иначе
`Safety: Safe`, `Categories: None`.
