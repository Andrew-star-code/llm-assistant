# config/prompts

Шаблоны промптов Jinja2 (§8.1). Изменение системного промпта — прогон `eval/scenarios` (с этапа 5).

| Шаблон | Назначение | Переменные |
| --- | --- | --- |
| `system/base.md.j2` | Базовые правила: кто ассистент, дата и время, язык, форматирование, безопасность | `company`, `now`, `timezone` |
| `system/user.md.j2` | Пользователь: ФИО, должность, отдел, форма обращения (§11.1) | `user.full_name`, `user.title`, `user.department`, `user.address` |
| `system/attachments.md.j2` | Вложения чата: целиком (`full`) или оглавление и начало (`outline`) + подсказка про инструменты чтения (§9.3) | `files[].name/type/pages/text/outline/preview`, `mode` |
| `system/knowledge.md.j2` | Фрагменты RAG с номерами для цитат `[n]` или пометка «ничего не найдено» (§10.4) | `fragments[].index/title/kb_name/page/section/text` |
| `utility/rag_query.md.j2` | Переформулировка запроса для поиска с дословным переносом кодов и ФИО (§10.4) | `history[].role/text`, `message` |
| `utility/title.md.j2` | Заголовок чата служебной моделью (3–6 слов) | `message` |

Порядок сборки системного промпта: `base` → `user` → ★ память → сценарий (этап 5) → контекст RAG
(этап 4) → вложения (этап 3). Дальше — история активной ветки и новое сообщение.

fake-llm опирается на четыре строки шаблонов, чтобы дев-стенд и тесты были детерминированы:
`Обращение к пользователю: …` (обращение в первом ответе), `Придумай короткий заголовок`
(сценарий заголовка), `Переформулируй запрос` (возвращает сообщение без изменений) и `=== Файл «…»`
(заголовок вложения в `system/attachments.md.j2`). Меняете их — обновите `services/fake-llm/src/fake_llm/scenarios.py`.
