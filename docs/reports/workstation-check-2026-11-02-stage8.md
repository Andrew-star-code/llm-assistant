## 3. Дефекты

### Дефект 1 ⚠️. После перезапуска api открытая вкладка зависает на оборванном ответе

Шаги: отправить «[[scenario:slow]] долго» → во время ответа выполнить `docker compose … restart api` → смотреть на вкладку.

Ожидаемо: «Генерация прервана» и кнопка «Повторить». Фактически вкладка остаётся на полуслове с кнопкой «Стоп»
([скриншот](assets/stage8/18-open-tab-after-restart.png)), поэтому отправить новое сообщение в этом чате нельзя:

```text
через  20 с: вкладка streaming, БД streaming
через  70 с: вкладка streaming, БД streaming
через 140 с: вкладка streaming, БД streaming
после F5:    вкладка interrupted, БД interrupted
```

Ответ без открытого чата остаётся `streaming` в БД, пока чат не откроют. После открытия всё верно: «Генерация прервана»,
«Повторить», [скриншот](assets/stage8/19-open-tab-reloaded.png). Воспроизведено 3 раза из 3.

**Причина подтверждена частично.** `restart` занимает 9,8–10,7 с, в логе `Waiting for connections to close`: похоже, открытый SSE не
даёт uvicorn завершиться, Docker обрывает его по тайм-ауту, и `generations.shutdown()` не успевает сохранить ответ. При старте
`mark_orphaned_interrupted` пропускает ответы с живым ключом `gen:alive:*` (TTL 30 с), а позже их никто не перепроверяет. Почему не
восстанавливается сама вкладка, не выяснено: возможно, важна цепочка через прокси Vite. На проде с nginx не проверялось. Вариант
исправления, не проверялся: повторять проверку после истечения TTL и добавить `stop_grace_period` у `api`.

### Дефект 2 ⚠️. «В личной базе уже 1 документов»

Шаги: политика «Документы личной базы = 1» → загрузить второй документ. Ожидаемо: верное склонение или формулировка без числа.
Причина в `kb`, в тексте отказа. [Скриншот](assets/stage8/15-kb-quota.png).
