# Задача: проверить этап 8 (лимиты) на рабочей станции

Ты работаешь в репозитории корпоративного ИИ-ассистента на рабочей станции разработчика: Windows + WSL2,
Docker Desktop. Правила проекта — в `AGENTS.md`, требования — в `docs/SPEC.md` (§12 — лимиты), прогресс и
демо-сценарии — в `docs/status.md` (раздел «Этап 8»). Общайся и пиши отчёт на русском. Образец отчёта —
`docs/reports/workstation-check-2026-11-01-stage7.md`.

## Цель

В облачной песочнице этап 8 проверен без настоящих `worker` и `scheduler` (задачи шли внутри api) и без
браузера на хосте. Нужно подтвердить на настоящих сервисах три критерия приёмки и демо этапа 8 и собрать
отчёт. **Код продукта не меняй.** Найдёшь дефект — опиши его с шагами воспроизведения; исправление можно
предложить отдельным коммитом в своей ветке.

## Что проверить

### 1. Автоматические проверки
```bash
make check
```
```bash

```
```bash
make test-worker
```
Запиши числа. Ожидается: pytest — около 292, из них несколько пропусков без LibreOffice/Tesseract на хосте;

отметь, повторилось ли); в `test-worker` первым шагом проходит `models`.

### 2. Сервисы и разделы учёта
- `docker compose ps`: `worker`, `worker-kb`, `scheduler` работают без перезапусков.
- В расписании `scheduler` есть `usage-partitions` (задача `limits.partitions`, раз в сутки в 03:27).
  Вызови её вручную на `worker`, например
  `celery -A app.workers.celery_app call limits.partitions` в контейнере `worker`, и убедись, что задача
  выполнилась без ошибок, а в БД есть `usage_records_default` и разделы текущего и двух следующих месяцев
  (`SELECT relname FROM pg_inherits i JOIN pg_class c ON c.oid = i.inhrelid WHERE i.inhparent =
  'usage_records'::regclass`).
- Нет `NoReferencedTableError`, `ImportError`, `Traceback` в логах `worker`, `worker-kb`, `scheduler`.

### 3. Демо этапа 8
Пройди все 7 шагов «Демо-сценария» этапа 8 из `docs/status.md` в браузере на http://localhost:5173. Особое
внимание:
- **Индикатор и сброс по часам компании.** Под полем ввода — «Осталось … из 2000 сообщений · обновится в
  00:00» (на дев-стенде лимиты выше прода). Запиши пояс Windows и браузера: время сброса должно быть по
  Москве, даже если пояс машины другой.
- **Учёт после ответа.** После ответа остаток уменьшается без перезагрузки (событие SSE `limits`). В БД у
  ответа есть строки `usage_records` вида `chat` и, для первого ответа чата, `title`; токены в «Лимитах»
  профиля равны сумме `prompt_tokens + completion_tokens` строк `chat`.
- **Критерий 1 (429).** При исчерпании — 429 `limit_exceeded` с `reset_at` (проверь ответ во вкладке Network)
  и текст «Дневной лимит сообщений исчерпан, обновится в 00:00. Если нужно больше — обратитесь к
  администратору.»; поле ввода закрыто.
- **Критерий 2 (персональная поверх ролевой, временная истекает).** Ролевая политика → в карточке
  пользователя источник «роль …»; временное повышение → «персональная, до …». Создай временную политику со
  сроком через 2–3 минуты (форма «Лимиты» → «до»), дождись срока и убедись, что без действий админа снова
  действует ролевая, а политика в списке с «Показать истёкшие» помечена «истекла».
- **Критерий 3 (одновременные ответы).** Три вкладки с разными чатами, в каждой «[[scenario:slow]] долго»:
  две генерации идут, третья получает «Одновременно можно вести не больше 2 ответов…». Дополнительно:
  перезапусти `api` (`docker compose … restart api`) во время двух генераций и проверь, что через
  `limits.slot_ttl_s` (120 с) слоты освободились сами и новые сообщения проходят.
- **Загрузки и личная база.** Ролевая политика «Документы личной базы = 1» → второй документ в «Моей базе
  знаний» получает отказ по квоте, а дневной лимит загрузок при этом не тратится.
- **Сброс и аудит.** «Сбросить счётчики» в карточке → у пользователя поле открыто после обновления страницы.
  В аудите — `limits.policy.create`, `limits.policy.update` (правка значения в таблице), `limits.policy.delete`,
  `limits.reset`.
- **Права.** У `kim` с ролью `kb_manager` раздела «Лимиты» нет, `/api/admin/limits/policies` → 403, прямая
  ссылка `/admin/limits` показывает «Недостаточно прав для этого раздела.»
- **Уборка.** В конце удали тестовые политики и сбрось счётчики пользователей, которых трогал.
