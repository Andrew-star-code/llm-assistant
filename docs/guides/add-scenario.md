# Как добавить корпоративный сценарий

Сценарий — запись в БД (§8.7): промпт, модель, инструменты, базы знаний, режим RAG, роли.
Создать его можно двумя способами; применяется он со следующего сообщения, без перезапуска.

## Из админки (обычный путь)

1. Админка → «Сценарии» → «Новый сценарий» (право `admin.scenarios.manage`).
2. **Код** — латиница (`hr_bot`), **название** и **описание** — то, что увидит пользователь на
   карточке, **иконка** — из списка.
3. **Промпт** — шаблон Jinja2, добавляется после базового системного промпта и данных пользователя.
   Переменные: `{{ user.full_name }}`, `{{ user.title }}`, `{{ user.department }}`,
   `{{ user.address }}`, `{{ company }}`, `{{ now }}`, `{{ scenario.name }}`. Шаблон рендерится в
   песочнице; ошибка синтаксиса не даст сохранить сценарий. Пишите, *как* работать и *в каком
   формате* отвечать; ссылки на источники — номерами `[n]`.
4. **Модель** — роль из реестра (`chat`, `coder`, `utility`…); «Размышлять» по умолчанию — как у
   модели, включено или выключено (ручной выбор пользователя в чате важнее).
5. **Режим RAG**: `авто` — поиск перед ответом + инструмент `search_knowledge_base`; `только
   инструмент` — модель ищет сама, когда нужно; `без RAG`.
6. **Базы знаний** — сужают поиск (ничего не отмечено — все базы, доступные пользователю; личная
   база пользователя ищется всегда). **Инструменты** — пересекаются с включёнными глобально и с
   правами пользователя; «все включённые» — без ограничений.
7. **Кто видит** — коды ролей (`legal`, `dept:Бухгалтерия`…); ничего не отмечено — всем. Роли из AD
   появляются при первом входе пользователя: если роли ещё нет, она показана как «появится при
   входе».
8. **Нужно вложение** + подсказка («Приложите договор») — без файла в чате отправить нельзя.
   **Примеры запросов** — до шести, показываются на стартовом экране при выборе сценария.
9. «Сохранить» → справа «Тестовый чат» → «Начать»: чат идёт с сохранённой версией, без проверки
   ролей, в историю не попадает. Правьте и сохраняйте — следующее сообщение тестового чата уже
   с новой версией.

Каждое изменение пишется в журнал аудита (какие поля изменены).

## Встроенный сценарий (seed в репозитории)

1. `config/scenarios/<код>.yaml` — поля как в редакторе (см. `contract_review.yaml`),
   `prompt_template: scenarios/<код>.md.j2`.
2. `config/prompts/scenarios/<код>.md.j2` — текст промпта.
3. При старте api сценарий добавляется в БД, **только если сценария с таким кодом ещё нет** —
   правки админа файл не перезаписывает. Чтобы обновить уже установленный сценарий, правьте его в
   админке (или удалите и перезапустите api).
4. `eval/scenarios/<код>.yaml` — 10–20 эталонных запросов с критериями (тест
   `test_every_builtin_scenario_has_10_to_20_cases` проверит, что они есть).
5. Тесты: `backend/tests/unit/test_scenarios_units.py::test_seed_files_are_valid` проверяет YAML,
   шаблон, инструменты и иконку. Документация: таблица в README модуля `scenarios`, CHANGELOG.

## Проверка качества

`make eval-scenarios` — ответы модели сценария на эталонные запросы и оценка служебной моделью-
судьёй; сравните со `eval/scenarios/baseline.json`, просмотрите выборку ответов в отчёте. Прогон
обязателен при смене модели или промпта.
