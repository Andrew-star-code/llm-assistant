# 0011. Разбор вложений: свои парсеры + LibreOffice + Tesseract, docling — опционально

- Статус: принято
- Дата: 2026-10-31

## Контекст

§9.3 требует отвечать по содержимому DOCX на десятки страниц и по сканам PDF, ссылаться на
страницы и показывать оглавление; всё офлайн, на одном сервере, рядом с моделями на GPU.
§4 называет docling, MarkItDown, LibreOffice и OCR. docling тянет PyTorch и модели разметки
(сотни мегабайт, их нужно класть на сервер заранее), а в песочнице разработки модели недоступны.

## Решение

- Разбор — в отдельном воркере Celery (образ api + LibreOffice, Tesseract `rus+eng`, шрифты),
  чтобы тяжёлые бинарники и падения конвертеров не задевали api.
- Основной путь — свои лёгкие парсеры: PyMuPDF (PDF, оглавление, рендер страниц для OCR),
  python-docx (страницы по разрывам, заголовки по стилям, таблицы), openpyxl, python-pptx,
  MarkItDown (HTML); старые и ODF-форматы — LibreOffice headless → OOXML.
- Страница без текстового слоя — OCR Tesseract. Результат — Markdown с маркерами
  `<!-- page: N -->` и оглавление в JSON: по ним работают `read_document` и ссылки на страницы.
- docling — адаптер за флагом `files.docling_enabled` (по умолчанию выключен): включается на
  сервере, когда его модели положены офлайн (этап 10) и сравнение на `eval/` покажет выигрыш.
- Генерация: pandoc из колеса `pypandoc-binary` (Markdown → DOCX с формулами OMML по
  `reference.docx`), PDF — DOCX через LibreOffice; XLSX — openpyxl; PPTX — python-pptx.

## Альтернативы

- docling для всего: лучше таблицы в сложных PDF, но PyTorch и модели в образе, медленнее на CPU,
  в песочнице не проверить. Оставлен опцией.
- Unstructured / Apache Tika: тяжелее (Java или много зависимостей), хуже контроль страниц.
- OCR через PaddleOCR/EasyOCR: точнее на сложных сканах, но PyTorch/Paddle и GPU-память,
  которая занята моделями.

## Последствия

- PyMuPDF — AGPL: для внутреннего сервиса без распространения допустимо; при поставке наружу —
  коммерческая лицензия или замена на pypdfium2.
- Качество таблиц в PDF без docling — текстом по строкам; при жалобах включаем docling.
- Образ воркера ~1 ГБ из-за LibreOffice; офлайн-бандл (этап 10) включает его.
- Бинарники проверяет `python -m app.cli worker check` (`make test-worker`).
