# 0003. Стриминг ответа: SSE + Redis Streams

- Статус: принято
- Дата: 2026-10-31

## Контекст

Ответ модели идёт потоком. Перезагрузка страницы или обрыв сети не должны терять ответ, а «Стоп»
может попасть в любой процесс `api` (§2.2).

## Решение

Генерация — фоновая asyncio-задача; каждое событие пишется в Redis Stream `gen:{message_id}`.
Браузер читает `GET /api/messages/{id}/stream` (SSE) и при обрыве переподключается с `Last-Event-ID`.
Отмена — флаг в Redis. Протокол — [sse-protocol.md](../architecture/sse-protocol.md).

## Альтернативы

WebSocket: двунаправленность не нужна, сложнее проходит через прокси, переподключение без потерь
пришлось бы делать самим.

## Последствия

nginx для SSE — без буферизации и с увеличенным `proxy_read_timeout`. Поток хранится в Redis ещё
10 минут после завершения, дальше состояние читается из БД.
