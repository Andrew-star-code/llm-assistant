# modules/scenarios

> Статус: реализовано на этапе 5 (§7.9, §8.7, §13.2).

**Назначение:** корпоративные сценарии — промпт, модель, инструменты, базы знаний, режим RAG,
thinking по умолчанию, «нужно вложение», примеры запросов, роли, которым сценарий виден.

**Как применяется (`completions/generation.py`):** сценарий чата читается из БД на каждое
сообщение — правка в админке действует со следующего сообщения, без перезапуска. Применяются:

| Поле | Что делает |
| --- | --- |
| `prompt_template` | Шаблон Jinja2 в песочнице после базового промпта и данных пользователя; переменные `user.*`, `company`, `now`, `scenario.name` |
| `model_role` | Роль модели из реестра (`chat`, `coder`, `utility`…); thinking доступен, если его поддерживает эта модель |
| `thinking_default` | Значение «Размышлять» для нового чата (ручной выбор пользователя важнее) |
| `tools` | Инструменты: включены глобально ∩ список сценария ∩ права пользователя; `null` — все |
| `knowledge_bases` | Коды баз: сужают область поиска; личная база пользователя остаётся; пусто — все доступные |
| `rag_mode` | `auto` — авто-поиск + инструмент, `tool` — только инструмент, `off` — без RAG |
| `requires_attachment` | Без файла в чате сообщение отклоняется с `attachment_hint` («Приложите договор») |
| `roles` | Коды ролей; пусто — всем. Чужой сценарий — 404; если роли сменились, чат продолжить нельзя, пока сценарий не сброшен |

**Публичный интерфейс:** `GET /api/scenarios` (карточки по ролям); `POST /api/chats` и
`PATCH /api/chats/{id}` с `scenario_id` (null — сброс); админка `GET/POST /api/admin/scenarios`,
`GET/PUT/DELETE /api/admin/scenarios/{id}`, `GET /api/admin/scenarios/options`,
`POST /api/admin/scenarios/{id}/test-chat` (тестовый чат без проверки ролей, не в истории).
Редактор проверяет шаблон, модель, инструменты и иконку; изменения — в аудит.

**Seed:** `config/scenarios/*.yaml` (+ промпт из `config/prompts/scenarios/`) при старте api
добавляются, если сценария с таким кодом ещё нет; дальше сценарий правят в админке, файл правки не
перезаписывает. Встроенные: «Анализ договоров», «ИТ-поддержка»; «Кадровый бот» — этап 9 (§9.5).

**Зависит от:** `rbac`, `tools`, `rag`, `kb`, `llm`, `audit`.
