# modules/rag

> Статус: реализовано на этапе 4 (§8.3, §10.2, §10.4, §10.5).

**Назначение:** гибридный поиск с реранкером по базам знаний и вложениям, область поиска по правам,
переформулировка запроса, источники ответа.

**Как работает поиск (`search.py`):**

1. Область (`Scope`) строит сервер при каждом запросе (`service.build_scope`): общие базы, ролевые по
   ролям пользователя, личные — только владельцу, вложения — только этого чата. Фильтр прав
   передаётся в каждый запрос к Qdrant; модель может область только сузить.
2. В каждой коллекции — запросы `dense` (40) и `bm25` (40, серверный `qdrant/bm25`, `russian`).
   Они идут отдельно, а не одним prefetch: так в трассировке видны ранги каждого списка, а отказ
   одного не роняет другой. Слияние — RRF (`1/(60 + ранг)`) или DBSF (`rag.search.fusion`).
3. До 60 лучших — в реранкер (`POST /v1/rerank`), порог 0,2, не больше 3 фрагментов с документа,
   итог 8; соседние чанки добавляются к тексту; номера `[n]` — сквозные на весь ответ (`SourceBook`).
4. Деградация: реранкер не ответил за 3 с → порядок RRF, 6 фрагментов; упал один из запросов →
   ищем по оставшемуся. Пропущенная стадия — в трассировке и инцидент `rag_degraded` (не чаще раза
   в 10 минут).
5. Трассировка: для каждого кандидата `chunk_id`, документ, ранги dense и BM25, RRF, балл реранкера,
   статус (`selected`, `below_threshold`, `per_document`, `beyond_final_k`) → `messages.trace.rag`.

**Режимы (§8.3):** `auto` — переформулировка служебной моделью (коды и ФИО дословно, BM25 получает и
исходный текст) → поиск → фрагменты в системный промпт (`system/knowledge.md.j2`) + инструмент
`search_knowledge_base`; `tool` — только инструмент; `off`. Пока режим — `rag.mode`, со сценариями
(этап 5) — из сценария.

**Хранилище (`store.py`):** коллекции `kb_chunks`, `personal_chunks` (`owner_id` — tenant-индекс),
`attachment_chunks`; векторы `dense` и `bm25` (IDF); id точки — `uuid5(document:version:index)`.
Новая версия пишется рядом и затем удаляет старые точки; удаление документа удаляет точки сразу.

**Публичный интерфейс:** `service.build_scope`, `service.run_search`, `service.rewrite_query`,
`store.write_document`, `store.delete_document`; источники — поле `sources` сообщения и событие SSE
`sources`.

**Зависит от:** `llm` (embed, rerank, utility), `kb`, `incidents`; Qdrant ≥ 1.15.3.

**Точки расширения:** провайдер BM25 `fastembed` (`TODO(stage-10)`), бонусы уровней
`rag.search.level_boost`, параметры подбираются на `eval/rag`.

**Данные:** `message_sources`; коллекции Qdrant выше.

**Тесты:** `backend/tests/integration/test_rag.py`, `backend/tests/unit/test_rag_units.py`, `eval/rag`.
