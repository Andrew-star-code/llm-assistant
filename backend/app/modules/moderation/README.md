# modules/moderation

> Статус: реализовано на этапе 7 (§9.6).

**Назначение:** политика модерации, скрытый репорт модели и вторая линия — guard-модель.

**Публичный интерфейс:**

* `policy.load_policy(config_dir)` — `config/moderation/policy.yaml`: категории репорта, уровни,
  текст нейтрального отказа, контакты помощи при угрозе себе, категории guard-модели;
  перечитывается при изменении файла.
* Скрытый инструмент `report_incident` (`tools/builtin/moderation.py`): инцидент `model_report`
  (категория, уровень, суть, цитата); не больше одного на чат за `moderation.report_window_s`,
  повторы — счётчик. Всегда предлагается модели, если не выключен в админке: сценарий его не
  убирает. Инструкция — отдельный шаблон `config/prompts/system/moderation.md.j2`, его не заменяет
  базовый промпт из админки.
* `guard.check` — проверка сообщения пользователя ролью `guard` (формат Qwen3Guard). Unsafe —
  инцидент `guard` с категориями и отрывком сообщения. По умолчанию фоном и без блокировки; если в
  админке «Настройки» выбраны категории для блокировки — до ответа модели, сработавшая категория
  даёт нейтральный отказ (`finish_reason = guard`).

**Скрытность — забота сервера** (§9.6): вызов скрытого инструмента не порождает событий SSE, не
отдаётся пользовательским API и поиском, не попадает в выгрузки пользователя; админ видит его в
карточке инцидента и в просмотре чата.

**Зависит от:** `incidents`, `llm`, `tools`, `admin.app_settings` (категории блокировки).

**Точки расширения:** новая категория — строка в `policy.yaml`; другая guard-модель — разбор
ответа в `guard.parse`.

**Данные:** инциденты `model_report` и `guard`; Redis `moderation:report:<chat>`.

**Тесты:** `backend/tests/integration/test_moderation.py`, `services/fake-llm/tests` (сценарий
`moderation`, ответы `fake-guard`).
